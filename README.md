# Job Researcher

잡코리아·원티드의 백엔드·풀스택 공고를 모으고, 로컬에서 회사별로 검토하는 도구.

## 실행

Node.js 24 이상과 Git이 필요합니다.

```sh
npm ci
npm run dev
```

[로컬 화면](http://127.0.0.1:4317)에서 공고를 확인하고 출발역을 설정합니다.

## 주요 기능

- 회사별 공고 추천과 신규·수정 구분
- 백엔드·웹·소프트웨어·AI 서비스 개발 목록 탐색, 회사·직무를 번갈아 상세 수집
- 회사 스킵·관심·지원 완료 기록
- 통근 시간 기록과 개인 상태 백업·복원
- GitHub Actions 정기 수집: 매일 한국시간 04:00, 기본 대상은 잡코리아

## 설계 원칙

- DB 서버와 LLM API 없이 JSON 파일로 저장하고 규칙으로 추천합니다.
- 백엔드·풀스택을 우선 선별하고, Go·Python·PHP·Java/Spring·Vue 등 공개 기술 프로필로 추천합니다.
- 일반 개발자 공고는 본문의 API·서버 업무와 기술 근거를 함께 확인합니다. 독립적인 프론트엔드·DevOps·인프라·데이터 직무는 제외합니다.
- 공개 공고는 `data/`, 수집 결과는 `reports/`에 보관합니다.
- 출발역과 개인 기록은 Git에서 제외한 `.local/`에만 저장합니다.
- 수집 실패 시 기존 데이터를 보존하고, 목록 누락만으로 마감 처리하지 않습니다.

## 점검

```sh
npm run collect                          # 두 사이트 수집
npm run collect -- --sources wanted       # 원티드만 로컬 수집
npm run collect -- --sources jobkorea     # 잡코리아만 수집
npm run check                            # 테스트·빌드·개인정보 검사
```

최근 수집 결과는 [reports/collection.json](reports/collection.json), 개발 규칙은 [AGENTS.md](AGENTS.md), 디자인 규칙은 [docs/design.md](docs/design.md)를 확인합니다.

## 원티드 자동 수집 환경

GitHub 호스팅 러너에서는 원티드 목록 API가 HTTP 403을 반환하므로 정기 실행 기본값은 `jobkorea`입니다. 원티드를 제외한 실행은 원티드 데이터와 마지막 수집 상태를 그대로 유지하며, Actions 요약에 미수집 사이트를 표시합니다. 두 사이트 전체가 갱신된 것으로 취급하지 않습니다.

원티드에 접근 가능한 자체 러너를 저장소에 등록한 뒤, 저장소의 Actions 변수에 `POLL_RUNNER=self-hosted`, `POLL_SOURCES=jobkorea,wanted`를 설정하면 정기 실행에서 두 사이트를 수집합니다. 자체 러너에는 Node.js 24를 실행할 수 있는 환경과 Git이 필요합니다. 직접 실행할 때는 **Run workflow**에서 `sources`와 `runner`를 함께 선택합니다. 직접 실행 입력은 정기 실행용 변수보다 우선합니다.

러너를 변경하기 전에는 해당 환경에서 `npm run collect -- --sources wanted --max-pages 1 --max-details 1`로 접근을 확인합니다. GitHub 호스팅 러너에서 원티드를 명시적으로 요청하면 차단은 계속 실패로 보고합니다. HTTP 403 자체를 해결하거나 무시하는 설정은 아닙니다.

## 현재 제한

- 잡코리아는 사이트의 공개 페이지 이동 POST, 원티드는 공개 목록·상세 API를 사용합니다. 원티드 상세 API가 실패하면 공개 공고 HTML도 확인합니다.
- Actions 요약에 사이트별 발견·저장·제외·실패 건수와 사유를 표시합니다. 페이지·상세 개수·시간 제한은 경고하고, HTTP 403·반복 페이지·상세 오류는 실패로 표시합니다. 부분 결과와 기존 공고는 보존합니다.
- 원티드는 Ubuntu·macOS GitHub 호스팅 러너에서 공개 목록 API도 HTTP 403으로 차단되는 것을 확인했습니다. 한국의 로컬 환경에서는 목록·상세 수집이 가능합니다. 자동 수집에는 접근 가능한 자체 실행 환경이 필요합니다.
- 채용 사이트가 실행 환경에 따라 접근을 제한할 수 있습니다. `접근 차단`이 표시되면 해당 사이트의 갱신은 완료되지 않은 상태이며, 로컬 수집으로 확인할 수 있습니다.
- 전체 수집은 사이트별 22분 안에서 진행합니다. 미확인 후보를 기존 공고 갱신보다 먼저 선택하고, 백엔드·풀스택·일반 개발 후보를 번갈아 확인합니다. 각 직무 안에서는 회사별로 공고를 하나씩 선택합니다. 같은 회사의 공고는 미확인·오래 확인하지 않은 순서로 확인해 일부 회사나 직무에 수집이 몰리지 않게 합니다. 전체 범위 검증은 남아 있습니다.
- 이미지 공고의 텍스트 추출, 통근 시간 자동 계산, 모바일 원격 접속은 지원하지 않습니다.
